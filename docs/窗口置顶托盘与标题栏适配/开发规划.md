## 1. 需求摘要

原始需求：
「1、可以设置窗口置顶功能，老板键随时隐藏窗口
2、隐藏窗口后是隐藏到托盘，任务栏中不要显示有任务窗口
3、缩小窗口大小后，标题栏中的设置选项会被隐藏掉（因为窗口不够大了）」

核心目标：给应用补上“置顶 + 托盘隐藏/恢复 + 标题栏自适应”三块能力，且不破坏现有阅读、书架、设置功能。

需求名称：`窗口置顶托盘与标题栏适配`（本需求全部材料位于 `docs/窗口置顶托盘与标题栏适配/`）

范围边界：
- 做：Tauri 托盘、窗口 hide/show、置顶 API 与持久化、两个页面的标题栏响应式、相关权限、最小宽度调整。
- 不做：阅读器功能重构、UI 大版改版、系统级全局热键、托盘气泡通知、开机自启。

## 4. 关键决策

- D-1：老板键沿用现有 `keyBindings.bossKey`。阅读页继续由 `Reader.vue` 处理（保持它现有的按键优先级）；书架页由 `App.vue` 新增分支处理，避免两套快捷键冲突。
  - 理由：最小改动，且不改变阅读页“上一章/下一章优先于老板键”的现有行为。
  - 放弃的方案：统一上移到 App 处理；会与阅读页现有按键优先级冲突，需要重排全部快捷键。
- D-2：托盘用 Tauri 2.9.5 内置 `tray-icon` feature，不新增第三方插件。
  - 理由：无新增依赖，改动集中在 `lib.rs`，当前 crate 缓存已有 `tray-icon`。
  - 放弃的方案：`tauri-plugin-tray` 等第三方插件；无必要。
- D-3：`window.hide()` 负责移除任务栏按钮；托盘菜单和左键点击负责 `show + unminimize + set_focus`。
  - 理由：hide 是 Windows 下移除任务栏按钮最直接的方式，同时保留进程和 WebView 状态。
- D-4：置顶状态放到 `DEFAULT_SETTINGS.alwaysOnTop`，复用现有设置存储；`App.vue` 启动时应用，并监听 `settingsChanged` 处理“恢复默认设置”。
  - 理由：沿用现有存储与事件机制，不新增存储键。
- D-5：两个标题栏用媒体查询切换紧凑模式；`minWidth` 从 100 调整为 320。
  - 理由：100px 无法容纳窗口控制按钮，320px 可保证设置和置顶按钮完整可用。
- D-6：关闭到托盘由前端 `onCloseRequested` 的 `event.preventDefault()` + `hide()` 负责，Rust 侧 `CloseRequested` 仅作兜底。
  - 理由：Tauri JS API 在关闭回调未阻止默认行为时会调用 `destroy()`；只做 Rust `prevent_close()` 仍会导致进程退出（实机验证发现）。
  - 影响：`App.vue` 的关闭回调必须保留 `event.preventDefault()`，否则托盘隐藏会退化为退出应用。

## 11. 交付说明

- 已完成的变更：窗口置顶（标题栏图钉 + 持久化 + 恢复默认同步）、托盘图标与显示/隐藏/退出菜单、老板键在书架和阅读页隐藏到托盘、关闭按钮改为隐藏到托盘、两个标题栏的窄窗口图标紧凑布局、最小宽度 320。

- 遗留问题与风险：托盘原生菜单的“显示/隐藏/退出”未做自动化点击，建议安装后手动点一次“退出”确认；点 × 不再退出应用，需从托盘菜单退出。
- 后续建议：如需托盘菜单也支持“置顶”开关，可复用 `alwaysOnTop` 设置和 `setWindowAlwaysOnTop()`。
